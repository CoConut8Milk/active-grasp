# 04 代码导读

按数据流顺序讲每个包。先读这一页建立心智模型，再看代码。

## 总览：一次「抓取」经历了什么

```
ag_agent/train.py          （决策循环）
    │  choose action
    ▼
ag_agent/env.py            （环境封装：调服务、算奖励）
    │  Grasp(u,v,height) 服务
    ▼
ag_execution/execution_node.py
    │  像素→世界坐标 (primitives.grid_to_xy)
    │  规划运动原语 (primitives.grasp_plan)
    │  IK 求解 (kinematics.RobotModel.ik)
    │  FollowJointTrajectory 动作
    ▼
ag_description/ag_arm.urdf（URDF → Gazebo + ros2_control）
    │  RGB-D 从仿真相机流出
    ▼
ag_perception/perception_node.py
    │  fusion.backproject：深度→3D 点
    │  fusion.make_snapshot：投影到 48×48 网格
    │  fusion.HeightmapFusion：高度+不确定度
    │  Observe 服务返回 6 通道状态
    ▼
ag_agent（reward / next state）
```

## ag_interfaces：五个服务

`Observe`（带 auxiliary_view 标志，返回 4 张图）、`Grasp`、`Push`、`MoveView`、
`Reset`。为什么用服务不用话题：强化学习是「一步一动作」的同步流程，阻塞式
服务调用最简单也最不容易出并发 bug。这是新手项目里值得学习的取舍。

## ag_description：机器人模型

- `urdf/ag_arm.urdf`：6 个旋转关节 + 2 个平行手指（移动关节）+ 腕部深度相机。
  全部用盒子/圆柱，零网格依赖。
- 相机几何要点：Gazebo Classic 相机沿 **+x** 看，所以 `camera_joint` 用
  `rpy="0 -1.5708 0"` 把相机 x 轴转到工具 z 方向。
- `<ros2_control>` 块声明 8 个关节的 position 命令接口；`config/ag_arm_controllers.yaml`
  定义三个控制器：`joint_state_broadcaster`、`arm_controller`（6 关节轨迹）、
  `gripper_controller`（2 手指位置）。

### 二指夹爪的「抓稳判定」

**方向约定（关键）**：URDF 里手指关节在 `tool0` 的 `z = -0.01`，指垫一直延伸到
`z = -0.07`，也就是手指沿 **-tool z** 伸出。因此抓取时 `tool z` 必须朝 **上**
（`grasp_orientation()` 返回单位阵），手指才会朝下；如果让 `tool z` 朝下，
指垫会跑到法兰**上方**（z=0.086~0.146 m），永远碰不到桌面上的物体。

手指行程设计成：全开间隙 5.6 cm，全闭间隙 0.4 cm（单指行程 2.6 cm），指尖在
`tool0` 下方 7 cm。开口留 1.1 cm/侧的余量，下降时不会把 3 cm 左右的物体撞飞。
执行节点读 `/joint_states` 得到 `width = 0.056 − (q_left + q_right)`，若
`0.008 < width < 0.051`，说明指面被物体挡住 → 抓取成功（`primitives.is_holding`）。

下降深度**不能**用固定偏移：那样指尖每次只比物体顶部低 5 mm，等于只掐住顶边，
物体一抬就滑掉。`grasp_plan` 现在把指尖放到物体高度的一半（且不低于桌面上方
1 cm），即 `tool_z = max(0.01, 0.5·z_top) + finger_length`。物体的随机尺寸也
限制在 4 cm 以内，保证能进入全开的指间。

## ag_gazebo：世界与物体

- `worlds/tabletop.world`：桌子（顶面 z=0.78）+ 回收盒 + 边界墙；机器人底座
  生成在 (0, 0, 0.78)。
- `worlds/tabletop_fast.world`：同场景，但 `real_time_update_rate=0`，
  物理跑满 CPU，训练专用。
- `world_manager.py`：`Reset` 服务删除旧物体、程序化生成新物体（随机形状/
  尺寸/颜色/摩擦/位姿），这就是「域随机化」的来源。物体 SDF 在代码里生成，
  不依赖模型文件。

## ag_perception：研究核心

`fusion.py` 是纯 numpy 模块，没有 ROS 依赖，所以能在任何机器单元测试：

1. `backproject`：深度图像 → 相机系 3D 点 → base 系；
2. `auto_calibrate`：利用「空桌是 z=0 平面」判定图像方向。注意**水平方向不可
   观测**：镜像后的桌面照样是平的（两种取号的方差都恰好为 0，见
   `test_flat_table_cannot_observe_horizontal_sign`），所以水平符号按相机约定
   固定为 -1，竖直符号（可观测，能发现相机倒装）由标定实测；
3. `make_snapshot`：3D 点投影进 48×48 网格，每格保留最高点及其颜色；
4. `HeightmapFusion`：维护 home 快照 + aux 快照，合成
   `不确定度 = 0.30×空洞 + 0.35×陈旧 + 0.35×边缘`。

`perception_node.py` 把它接进 ROS：订阅深度/彩色/相机内参/关节速度，维护 TF，
提供 `observe` / `clear` / `clear_aux` 服务。启动时用定时器等待机械臂回到
home，再在空桌上做相机标定——所以**世界管理器只在收到 Reset 时才生成物体**。

## ag_execution：运动学与动作

- `kinematics.py`：`RobotModel` 从 URDF 解析关节树，FK 用 BFS 顺序复合变换，
  IK 用 `scipy.optimize.least_squares` 最小化 6D 位姿误差（位置 + 0.35×旋转
  向量），支持多重启动种子。关节限位来自 URDF。
- `primitives.py`：抓/推/看三种动作的步骤序列。抓取 = 接近→下降→闭爪→
  抓稳判定→抬起→去回收盒→放爪→home；推动 = 下探→水平扫 9 cm→抬起；
  换视角 = 去视角位姿→停留（触发感知融合）→home。
- `execution_node.py`：把步骤转成 `FollowJointTrajectory` 动作，夹爪走
  `gripper_controller/commands` 话题。**每个服务都做失败恢复**：任何一步失败
  都会张开手指回 home，而不是让机械臂卡在半路。

### 视角位姿怎么定义

`execution.yaml` 里每个视角是相机的位置 + 注视点。执行节点用
`look_at_matrix` 构造相机姿态，再用「相机在工具系里的固定变换」反解出工具
位姿去做 IK。好处：你在配置文件里改视角坐标即可，不用重算任何机械臂参数。

## ag_agent：强化学习

- `actions.py`：动作空间 = 抓(48×48) + 推(48×48×8) + 看(4)。注意推动块是
  **方向优先**排布，与网络输出的展平顺序严格一致（单测覆盖了这个易错点）。
- `env.py`：把服务调用封装成 `reset / step / observe / valid_mask`，并在
  `step` 里算奖励。抓/推之后调 `clear_aux`（世界变了，备用视角作废）。
- `network.py`：膨胀卷积 FCN。骨干保持 48×48 分辨率，三个头分别输出抓取
  Q 图、8 个推动方向 Q 图、4 个视角 Q 值。
- `agent.py`：DDQN（online 选动作 + target 估值）、ε-greedy、梯度裁剪、
  目标网络定期同步。
- `train.py`：课程学习——近 20 回合平均清理率 ≥0.7 就加一个物体，≤0.3 就减。
- `baselines.py`：贪心策略（抓最高点，失败两次就推向中心，从不换视角）和
  随机策略。

### 状态张量的 6 个通道

`[高度/z_max, 不确定度, R, G, B, 占据掩码]`。高度除以 0.35 归一化，
RGB 除以 255。`valid_mask` 用第 6 通道判断哪些格子可以抓/推，视角动作永远合法。

## ag_bringup：编排

`sim.launch.py` 按顺序拉起 Gazebo（实时/加速两套世界）、robot_state_publisher、
生成机器人、ros2_control + 三个控制器 spawner、世界管理器、感知、执行。
`ag_agent/launch/*.launch.py` 在它之上再挂训练/评估/演示节点。

## 修改指南（把项目变成「你的」）

| 想改什么 | 改哪里 |
|---|---|
| 物体种类/数量上限 | `world_manager.py` 的 `build_object_sdf`、Reset 上限 |
| 视角个数与位置 | `execution.yaml` 的 `views_flat`（每 6 个数一个视角）+ `ag_agent/config/agent.yaml` 的 `n_views` |
| 网格分辨率 | 三处 `grid_width/height` 配置 + `env.py` 默认值（要一致） |
| 不确定度权重 | `fusion.py` 的 `w_hole/w_age/w_edge` |
| 奖励系数 | `env.py` 的 `step` 分支 |
| 网络结构 | `network.py` |
| 换一种手臂 | 换 URDF + 保持 `RobotModel` 解析兼容（6 旋转关节） |
